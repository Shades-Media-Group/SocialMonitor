# Contributing to SocialMonitor

Thanks for helping make SocialMonitor better. Bug reports, ideas and pull requests are all welcome.

## Report a problem

- **Something broke?** Open a [bug report](https://github.com/Shades-Media-Group/SocialMonitor/issues/new?template=bug.yml). Never paste real comments, names or exported data.
- **An idea?** Start a [discussion](https://github.com/Shades-Media-Group/SocialMonitor/discussions) or open a [feature request](https://github.com/Shades-Media-Group/SocialMonitor/issues/new?template=feature.yml).

Security issues go through [private reporting](SECURITY.md), never public issues.

## Set up

You need Node 22.18 or newer (see `.nvmrc`) and Yarn 1.

```bash
git clone https://github.com/Shades-Media-Group/SocialMonitor.git
cd SocialMonitor
yarn install
yarn verify
```

## How the code is organised

| Path           | What it does                                                                  |
| -------------- | ----------------------------------------------------------------------------- |
| `apps/app`     | The dashboard: local server, database, collectors, AI sorting, scheduler, MCP |
| `apps/site`    | The website, socialmonitor.shades.md, served by a Cloudflare Worker           |
| `assets/brand` | Logo files, generated by `scripts/brand.mjs`                                  |
| `docs`         | Guides for running, scheduling, the MCP server and data                       |
| `scripts`      | Brand, SEO check and release scripts                                          |
| `data`         | Your local database, browser profile and reports. Git-ignored.                |

## Before you open a pull request

```bash
yarn verify      # typecheck, lint, unit tests and the website build
```

- Keep each pull request to one change, and add a test when you change how posts or comments are read or sorted.
- Use [Conventional Commits](https://www.conventionalcommits.org/): `feat(app): …`, `fix(site): …`, `docs: …`. The changelog is generated from them.
- Interface changes follow the design rules in [CLAUDE.md](CLAUDE.md#design-rules). Include before and after screenshots in light and dark, with sample data rather than real people's comments.
- Generated files (`assets/brand/**`, `apps/app/src/web/brand.ts`) are never edited by hand: change the script and run it.

## Ground rules

- SocialMonitor stays free, with no accounts, limits or paid tiers.
- The dashboard is never hosted. Data stays on the user's computer, apart from the text sent to Claude for sorting.

By contributing you agree that your work is released under the [MIT License](LICENSE), and that you'll follow the [Code of Conduct](CODE_OF_CONDUCT.md).
